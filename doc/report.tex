\section{Introduction}

Labelme is a widely used, open-source graphical image annotation tool that
enables users to label objects in images for computer vision tasks. Developed
in Python and using the Qt library for its graphical interface, it is
cross-platform and supports a variety of annotation types, including polygons,
rectangles, circles, lines, and points. This versatility makes it suitable for
diverse tasks such as object detection, semantic segmentation, and instance
segmentation.

For every annotated image, Labelme generates a corresponding JSON file. This
file contains metadata about the image (such as its path and dimensions) and a
detailed list of shapes representing the annotations, including their label
names and coordinate points. The output of a dataset annotated with Labelme is
typically structured as shown in Fig. \ref{fig:labelme_structure}.

\begin{figure}[htbp]
\dirtree{%
	.1 labelme\_dataset/.
	.2 img1.json.
	.2 img1.jpg.
	.2 img2.json.
	.2 img2.png.
	.2 subdirectory/.
	.3 img3.json.
	.3 img3.jpg.
	.2 \ldots.
}
\caption{Structure of a Labelme dataset}
\label{fig:labelme_structure}
\end{figure}

While this structure is rich in information and easy to parse programmatically,
it is not directly compatible with the input requirements of popular deep
learning frameworks and model architectures. Frameworks like Darknet/YOLO,
standard COCO-based models, or Pascal VOC-based pipelines require annotations
in specific formats---such as aggregated JSONs, flat text files with normalized
coordinates, or XML files---often accompanied by strict directory structures.

The goal of the Labelme converter is to bridge this gap. It serves as a
comprehensive tool that parses the raw Labelme dataset and transforms it into a
format ready for the training process of a neural network, thereby streamlining
the workflow from data annotation to model training.

\section{Methodology and Implementation}

This section details the workflow adopted for the project, encompassing manual
data annotation, semi-supervised simulation, and data format conversion. The
process was designed to demonstrate a complete pipeline from raw data to
model-ready datasets.

\subsection{Instance-based Annotation (Supervised)}

To establish a ground truth, we employed an instance-based annotation approach
using the Labelme tool. A subset of 20 images was selected from the Clothing
Co-Parsing (CCP) Dataset\footnote{\url{https://www.kaggle.com/datasets/balraj98/clothing-coparsing-dataset}}.
This dataset was chosen for its high-resolution images and complex subject
boundaries.

For these images, we manually labeled the "head" class. Two distinct annotation
modes were used to rigorously test the system:

\begin{itemize}
    \item \textbf{Rectangle Mode:} Objects were bounded by rectangular boxes.
	    This represents a coarser form of supervision, typically used for
		object detection tasks.
    \item \textbf{Polygon Mode:} Objects were outlined with precise polygonal
	    chains. This represents fine-grained, pixel-level supervision
		required for instance segmentation.
\end{itemize}

\subsection{Semi-supervised Annotation Simulation}

To simulate a semi-supervised annotation workflow, we leveraged the initial set
of manual annotations to automate the labeling process for the broader dataset.
A custom Python function was developed to reuse the manually defined annotation
logic and apply it across similar images. This approach mimics real-world
scenarios where a small set of labeled data is used to bootstrap the annotation
of a larger unlabeled pool, significantly reducing manual effort.

\subsection{Data Conversion Workflow}

The final stage of the implementation involved converting these annotated
datasets into industry-standard formats. We developed a Python-based converter
tool that parses the Labelme JSON outputs and systematically transforms them
into YOLO, COCO, and Pascal VOC formats. This ensures that the data, whether
manually labeled or semi-automatically generated, is immediately usable by
standard deep learning frameworks.

\section{Converter}

The Labelme converter is a Python-based command-line tool designed to transform
datasets annotated in Labelme into standard formats required by major computer
vision frameworks. The tool adopts a modular architecture, where each target
format is handled by a specialized module. This design allows for easy
extensibility and maintenance.

As of writing this report, the converter supports the following target formats:
\begin{itemize}
    \item \textbf{COCO:} Standard JSON-based format for object detection and
	    segmentation.
    \item \textbf{YOLO:} Flat text-file format with normalized coordinates,
	    optimized for the YOLO family of models.
    \item \textbf{Pascal VOC:} XML-based format for detection, accompanied by
	    PNG masks for segmentation.
\end{itemize}

\subsection{labelme2coco module}

The \texttt{labelme2coco} module aggregates all annotations into a single JSON
file (or two, if splitting for training/validation). It is ideal for instance
segmentation tasks as it preserves the exact polygonal coordinates defined in
Labelme.

The module supports random splitting of the dataset based on a user-defined
ratio. The output directory structure is shown in Fig.
\ref{fig:coco_structure}.

	.3 \ldots.
	.2 train/.
	.3 000000000001.jpg.
	.3 000000000002.jpg.
	.3 \ldots.
	.2 val/.
	.3 000000000501.jpg.
	.3 000000000502.jpg.
	.3 \ldots.
}
\caption{Structure of the generated COCO dataset}
\label{fig:coco_structure}
\end{figure}

The generated JSON files adhere strictly to the COCO schema. Listing
\ref{lst:coco_json} illustrates the key fields. Note that the
\texttt{segmentation} field retains the polygon points, while \texttt{bbox} and
\texttt{area} are automatically calculated from the shape.

\begin{lstlisting}[style=json, caption={Example COCO format JSON file}, label={lst:coco_json}]
{
	"images": [
		{
			"id": 1,
			"width": 800,
			"height": 600
			"file_name": "000000000001.jpg",
		},
		...
	],
	"annotations": [
		{
			"id": 1,
			"image_id": 1,
			"category_id": 1,
			"segmentation": [[x1, y1, x2, y2, ...]],
			"area": 123.45,
			"bbox": [x, y, width, height]
			"iscrowd": 0,
		},
		...
	],
	"categories": [
		{
			"supercategory": "superclass1"
			"id": 1,
			"name": "class1"
		}
	]
}
\end{lstlisting}

\subsection{labelme2yolo module}

The \texttt{labelme2yolo} module is designed for object detection workflows
(specifically YOLOv8). A key feature of this module is the normalization of
coordinates. Regardless of whether the input is a rectangle or a polygon, the
module calculates the bounding box and converts coordinates to the range $[0,
1]$ relative to the image dimensions.

The output directory contains a \texttt{dataset.yaml} configuration file and
separate text files for each image, organized into train/val folders as shown
in Fig. \ref{fig:yolo_structure}.

\begin{figure}[htbp]

	.3 train/.
	.4 img001.jpg.
	.4 \ldots.
	.3 val/.
	.4 img101.jpg.
	.4 \ldots.
	.2 labels/.
	.3 train/.
	.4 img001.txt.
	.4 \ldots.
	.3 val/.
	.4 img101.txt.
	.4 \ldots.
}
\caption{Structure of the generated YOLO dataset}
\label{fig:yolo_structure}
\end{figure}

The \texttt{dataset.yaml} file (Listing \ref{lst:yolo_yaml}) defines the
dataset paths and class names, which is essential for training YOLO models.

\begin{lstlisting}[style=json, caption={Example YOLO format dataset.yaml file}, label={lst:yolo_yaml}]
path: absolute/path/to/yolov8_dataset
train: images/train
val: images/val
test:

names:
	0: class1
	1: class2
	2: class3
	...
\end{lstlisting}

The annotation text files use the standard YOLO format: \texttt{<class\_id>
<x\_center> <y\_center> <width> <height>}, as shown in Listing
\ref{lst:yolo_txt}. All values are normalized.

\begin{lstlisting}[style=json, caption={Example YOLO format text file}, label={lst:yolo_txt}]
	class_id1 x_center y_center width height
	class_id2 x_center y_center width height
	...
\end{lstlisting}

These values should be calculated based on the shape type and the
coordinates of the shape.

\subsection{labelme2voc module}

The \texttt{labelme2voc} module generates a dataset complying with the Pascal
VOC standard. This module is unique because it handles both object detection
and semantic segmentation simultaneously.

For detection, it generates XML files containing bounding boxes for all
annotated shapes (polygons are converted to their enclosing bounding boxes).
For segmentation, it rasterizes the polygons and rectangles into pixel-wise
masks (PNG images), saved in the \texttt{SegmentationClass} and
\texttt{SegmentationObject} directories.

The output directory is populated with the standard Pascal VOC folder structure,
as shown in Fig. \ref{fig:voc_structure}. The module ensures that the generated
files, including XML annotations and segmentation masks, are organized according
to the VOC specification within this structure.

The `ImageSets` directory contains text files (e.g., `train.txt`, `val.txt`)
that list the filenames of images belonging to each split, as shown in
Listing \ref{lst:voc_txt}.

\begin{lstlisting}[style=json, caption={Example Pascal VOC ImageSet text file}, label={lst:voc_txt}]
000001.jpg
000002.jpg
...
\end{lstlisting}

The XML files in the `Annotations` directory contain the object annotations
for each image. A key aspect of transforming Labelme data to Pascal VOC is
converting complex shapes like polygons and circles into axis-aligned bounding
boxes for the XML format. This is achieved by determining the minimum and
maximum coordinates of the shape.

The XML files follow the standard VOC schema, an example of which is shown
in Listing \ref{lst:voc_xml}. Note that for our dataset, the class name will
be "head".

\begin{lstlisting}[style=json, caption={Example Pascal VOC XML annotation file}, label={lst:voc_xml}]
<annotation>
    <folder>VOC2012</folder>
    <filename>000001.jpg</filename>
    <object>
        <name>head</name>
        <bndbox>
            <xmin>100</xmin>
            <ymin>100</ymin>
            <xmax>200</xmax>
            <ymax>200</ymax>
        </bndbox>
    </object>
</annotation>
\end{lstlisting}
